# Security policy

## Report a vulnerability

Use a [private GitHub security advisory](https://github.com/wuxiangcoding/vibecodinghub-seo-skills/security/advisories/new). Do not open a public issue for a vulnerability or include credentials, property identifiers, queries, URLs, metrics, exports, or snapshots in a report.

Include a minimal reproduction with synthetic values, affected versions, impact, and any suggested mitigation. Maintainers will acknowledge a valid report as soon as practical and coordinate remediation before public disclosure.

## If data was exposed

Revoke or rotate the affected provider credential first. Remove the data from Git history, CI artifacts, terminal recordings, issue attachments, and other log sinks. Deleting only the latest file is not sufficient.

## Supported versions

Security fixes target the latest released minor version. Versions before `1.0.0` may introduce breaking changes between minor releases.
